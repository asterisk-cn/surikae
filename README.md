# すりかえ

震えだけが見えるカードゲーム．3レーン・魔法・見せかけ・パスの読み合い．

## 開発

パッケージマネージャは pnpm（`packageManager` に固定．corepackが有効なら
リポジトリを開くだけで版が揃う）．

```sh
pnpm install
pnpm dev        # Vite開発サーバー（CPU戦・同一ブラウザ検証モード）
pnpm sim        # バランスシミュレーション（20000戦×複数条件）
pnpm test:net   # NetSession整合性テスト（500戦）
```

オンライン対戦をローカルで試すには，ビルドしてからwrangler devで
静的ファイルとWebSocketサーバーを同居させる：

```sh
pnpm build
pnpm exec wrangler dev   # http://localhost:8787
```

（開発サンドボックス等，外部への疎通が制限された環境ではminiflareが
起動時のcf.json取得に失敗して立ち上がらないことがある．通常環境では動く）

## デプロイ（Cloudflare Workers + Durable Objects）

公開先は `https://surikae.astrsk.work`（wrangler.jsonc の `routes` で指定．
astrsk.work がCloudflareのゾーンとして同じアカウントに載っていることが前提）．


```sh
pnpm run deploy
```

`deploy` は pnpm 自身のコマンドと名前が衝突するので，`pnpm run` を省けない
（`pnpm deploy` はワークスペースの取り出しになってしまう）．
初回は `pnpm exec wrangler login` が必要．無料プランで動く
（Durable ObjectsはSQLiteバックエンド指定済み）．

## 情報構造

- 開始時に6枚すべてを3秒だけ相互公開し，**自分の3枚も含めて**自動で伏せる
  （共有知識の基準線．以降，自分の手札も記憶だけが頼りになる）
- 以降，盤上の札は一切見えない．震えたレーンだけが観測できる
- ヤマとの交換で引いた札は，**1秒だけ両者に開示されてから**伏せられる
  （値は共有知識になるが，どちらも覚えていなければならない）
- 相手との交換は互いに伏せたまま受け取るので，**双方が自分のその札の正体を失う**
- 見せかけの交換（後述）でも，渡された側は同じように正体を失う．
  本物と区別がつかない以上，知識の失われ方も同じでなければならない
- `known[p][lane]` がこの知識状態を追跡する

## 見せかけ（ブラフ）

震えは行動の実体を伴わずに起こせる．打てるのは2種類：

- **入れ替えのふり** … 自分の2レーンを選んで「見せかけ」
- **奪うふり** … 自分1枚＋相手1枚を選んで「見せかけ」

作り変えのふり（1枚だけの震え）は無い．ヤマから引いた札はその場で開示されるので，
札が出なければ嘘だと分かってしまう．

奪うふりについて：

- 信号は本物のxswapと完全に同一（自分側1レーン＋相手側1レーン）
- 本物の回数を使い切っていても打てる．「使ったふり」で本物を温存することも，
  使い切ったあとで「まだ持っている」と見せることもできる
- コウ（取り返しの禁止）のときだけは打てない．そこは本物も打てないと
  相手に分かっているので，嘘が透ける
- コウ自体も観測された記録で判定するので，見せかけの交換でも相手に掛かる
- 各自の本物は `xswapPerPlayer` 回まで．交換の信号をk回出せば，そのうち
  少なくとも k − 上限 回は嘘だと相手に分かる（どれが嘘かは分からない）．
  CPUの信念モデルもk度目の信号の本物らしさを 上限/k 倍に割り引く

## 通信プロトコル

- `join` … 入室通知（joiner→host）
- `init` … 初期公開手札と先手（host→joiner）
- `shake` … 震えたレーン（0枚＝パス）．見せかけの交換のときだけ
  `foreign` に相手側のレーンが，ヤマとの交換のときだけ `drew` に引いた札が載る
- `xswap` / `xack` … 相手との交換．渡す札だけを送り，受け取る札は返信で届く．
  ただし双方とも受け取った札は伏せたままで，正体は決着まで分からない
- `reveal` … 決着時の手札と行動ログ（リプレイ用）
